## ทำไมต้องเป็น webapp

โรดแมป **R-04** เขียนไว้ตรง ๆ ว่าการย้ายออกจาก artifact sandbox มาเป็นเว็บแอปภายใน
คือ *เงื่อนไขที่ต้องทำก่อน* จึงจะเก็บ override ถาวรได้ — เพราะ Cowork artifact
ใช้ `localStorage` ไม่ได้ ทำให้ override หายทุกครั้งที่รีเฟรช (ข้อจำกัด **C-01** ใน SRS §5.2)

เวอร์ชันนี้ปิดข้อจำกัดนั้นแล้ว

### ข้อความ TC-34 ถูกแก้โดยตั้งใจ

UAT **TC-34** คาดหวังข้อความว่า *"override เก็บชั่วคราว ต้อง Export เพื่อบันทึกถาวร"*
ในเวอร์ชันนี้ข้อความนั้น**ไม่จริงแล้ว** จึงถูกเปลี่ยนเป็น
*"✓ บันทึกไว้บนเครื่องนี้แล้ว — รีเฟรชได้ไม่หาย · Export Excel คือ audit trail ที่ใช้ส่งต่อ"*

ถ้าเบราว์เซอร์ปิดที่เก็บข้อมูล (โหมดส่วนตัว/นโยบายองค์กร) ข้อความจะถอยกลับไปเตือนแบบเดิมอัตโนมัติ
— **ต้องอัปเดต UAT TC-34 และคู่มือสไลด์ 16 · 21 · 22 ให้ตรงกันก่อน UAT รอบถัดไป**

### ความเสี่ยงใหม่ที่มาพร้อมการเก็บถาวร

ของเดิม override หายทุกรีเฟรช จึงไม่มีทางค้างข้ามรอบ
พอเก็บถาวรแล้ว ตัวเลขรอบที่แล้วอาจทับรอบใหม่เงียบ ๆ — ซึ่งขัดกับคู่มือสไลด์ 21
ที่สั่งให้ทบทวน override รอบก่อนทุกครั้ง

ระบบจึงเทียบเดือนใน override กับเดือนเป้าหมายปัจจุบัน แล้วขึ้นเตือนพร้อมปุ่ม
**"ล้างเฉพาะของรอบก่อน"** ที่ไม่แตะรายการของรอบปัจจุบัน

## ภาษา TH / EN

ปุ่มสลับอยู่ท้ายแถบเมนู · **ไทยเป็นค่าตั้งต้นเสมอ** ตาม NFR-05 — อังกฤษเป็นทางเลือกที่เพิ่มเข้ามา
ไม่ได้แทนที่ · ระบบจำภาษาที่เลือกไว้

**วิธีทำงาน:** พจนานุกรมใช้ *ข้อความไทย* เป็นคีย์ตรง ๆ ไม่ใช้รหัสคีย์ จึงไม่ต้องแก้ `index.html`
สักบรรทัด และข้อความที่ JS สร้างตอน render ก็ถูกแปลด้วยกลไกเดียวกัน เพราะระบบเดินอ่าน
text node หลัง render · ข้อความที่ยังไม่มีคำแปลจะ**คงเป็นภาษาไทย** ไม่มีทางขึ้นคีย์ดิบหรือค่าว่าง

**ที่ไม่แปลโดยตั้งใจ:**

| | เหตุผล |
|---|---|
| ชื่อสินค้า / เมนู / หมวด | เป็น **ข้อมูล** ไม่ใช่ UI — มาจาก `DATA` |
| กฎจับกลุ่มช่องทาง (`#mchrules`) | เป็น **คำค้นที่เอาไปจับคู่จริง** ใน `parseChRules()` ถ้าแปล `แฟรนไชส์`→`franchise` การจับกลุ่มสาขาไทยจะพังเงียบ ๆ — เอนจินกัน `<textarea>` ไว้ทั้งหมด |
| หัวตารางไฟล์ส่งออก | เป็น **สัญญาข้อมูล** — SRS §5.3 กำหนดโครงสร้างไว้ UAT TC-37–42 ตรวจตามนั้น และ R-02 จะให้ Power Query อ้างคอลัมน์เหล่านี้ ถ้าเปลี่ยนตามภาษา integration จะพัง |

**label เดือนต่างกันตามภาษา:** ไทยใช้ พ.ศ. ย่อ (`ส.ค. 69`) อังกฤษใช้ ค.ศ. เต็ม (`Aug 2026`)
เพราะ พ.ศ. ย่อสื่อผิดกับผู้อ่านต่างชาติ

> ผลข้างเคียงที่เจอและแก้แล้ว: เดิม override เก็บ "เดือน" เป็น *label* ซึ่งผูกกับภาษา
> พอสลับภาษาแล้วระบบจะเข้าใจผิดว่า override ทุกตัวเป็นของรอบก่อน — เปลี่ยนไปเก็บเป็น
> คีย์เดือน `2026-08` แทน และมี migration ทิ้งค่าเก่าที่เป็น label

## ที่เก็บข้อมูล

ทุกอย่างอยู่ใน `localStorage` ใต้ prefix `jc.ibp.v1.` บนเครื่องผู้ใช้เท่านั้น

| คีย์ | เนื้อหา |
|---|---|
| `ovr` | override · เหตุผล · ผู้ทบทวน · เดือนเป้าหมาย (`at`) · timestamp |
| `params` | holdout · α · ขั้นต่ำประวัติ · gap · วิธี · สวิตช์ต่าง ๆ |
| `prefs` | ชื่อผู้ทบทวน · กฎจับกลุ่มช่องทาง |
| `core` | lead time · target cover · เกณฑ์ ABC (ไม่เก็บฐาน Suggested PR — NFR-09 ต้องกลับค่าตั้งต้นเสมอ) |
| `session` | ชุดข้อมูลที่ประมวลผลแล้ว (series ไม่ใช่ไฟล์ดิบ) |
| `lang` | ภาษาที่เลือก |

**ยังไม่ขัด NFR-02** — ไม่มี network call ที่บรรจุข้อมูลยอดขาย ไฟล์ยังไม่ออกจากเครื่อง
และ `_headers` / `nginx.conf` ตั้ง `connect-src 'none'` ให้เบราว์เซอร์บังคับข้อนี้อีกชั้น

เมื่อโควตาเต็ม ระบบจะทิ้ง `session` ก่อนแล้วลองใหม่ เพื่อให้ override รอด —
แต่**เฉพาะตอนเขียนคีย์ที่สำคัญกว่า** (`ovr` `params` `prefs` `core`) เท่านั้น
การกดสลับภาษาจะไม่ทำให้ชุดข้อมูลทั้งรอบหายอีกต่อไป

ถ้าเขียนลงดิสก์ไม่สำเร็จ ค่าจะถอยไปเก็บในหน่วยความจำ และป้ายใต้ตารางจะ
**เปลี่ยนเป็นคำเตือน** ไม่ใช่ขึ้น "✓ บันทึกแล้ว" ทั้งที่ยังไม่ได้บันทึก

**ยังไม่ครบ R-04 เต็มรูป** — R-04 กำหนดให้ชื่อผู้แก้มาจากบัญชีที่ล็อกอิน
ไม่ใช่ช่องข้อความ และให้เก็บบน corporate data layer (SharePoint/Dataverse/SQL)
ตอนนี้ยังเป็นการเก็บระดับเครื่อง + ประกาศตนเองตาม SRS §6.1
ถ้าเปลี่ยนเครื่องหรือล้างเบราว์เซอร์ ข้อมูลหาย — **Export Excel ยังเป็น audit trail ที่ต้องส่งต่อ**
